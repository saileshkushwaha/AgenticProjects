# Workflow 35: Retrospective

**Duration**: 1-4h | **Outputs**: Retrospective report, action items, improvement plan

## Trigger
- Sprint/phase end, project completion, incident follow-up
- Team feedback session, process improvement initiative

## Steps

### Step 1: Gather Data
Collect metrics, feedback, and observations from the sprint/phase.
**Time**: 15-30 min.

### Step 2: Identify What Went Well
Document successes and positive outcomes.
**Time**: 15-30 min.

### Step 3: Identify What Went Wrong
Document challenges, failures, and root causes.
**Time**: 30-60 min.

### Step 4: Extract Lessons Learned
Synthesize findings into actionable lessons.
**Time**: 15-30 min.

### Step 5: Create Action Items
Define specific, measurable improvements.
**Time**: 15-30 min.

### Step 6: Document and Share
Publish retrospective report and track action items.
**Time**: 15-30 min.

## Quality Gates

| Gate | Criteria |
|------|----------|
| QG1 | Data gathered from multiple sources |
| QG2 | Both positives and negatives documented |
| QG3 | Root causes identified |
| QG4 | Action items defined with owners |
| QG5 | Report published and shared |

## Anti-Patterns

1. **Blame culture** — Focusing on who not what
2. **No follow-through** — Not tracking action items
3. **Surface-level analysis** — Not identifying root causes
4. **Excluding team members** — Not gathering all perspectives

## Edge Cases

- Remote teams → Use async retrospective tools
- Conflict situations → Use facilitated retrospective
- No metrics available → Rely on qualitative feedback
