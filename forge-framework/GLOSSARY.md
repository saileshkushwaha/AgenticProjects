# Glossary - Forge Engineering Lifecycle Framework

## A
- **ADR**: Architecture Decision Record - captures significant design decisions
- **Acceptance Criteria**: Conditions for a requirement to be considered complete
- **Analysis**: Phase evaluating requirements, feasibility, risks, and trade-offs
- **Artifact**: Any documented output produced during the SDLC

## B
- **Best Practice**: Technique generally accepted as superior based on proven results
- **Blue-Green Deployment**: Two identical environments, switch traffic for zero-downtime
- **Branching Strategy**: Convention for code branch management (GitFlow, trunk-based)

## C
- **Canary Deployment**: Gradual rollout to subset of users before full deployment
- **CI/CD**: Continuous Integration/Continuous Deployment - automating build, test, deploy
- **Code Coverage**: Proportion of source code executed during testing
- **Constraint**: Limitation affecting the solution space (technical, business, regulatory)

## D
- **Debug**: Process of identifying, isolating, and resolving defects
- **Defect**: Flaw causing unexpected behavior or incorrect results
- **Design**: Phase creating architecture, components, data models, APIs
- **DRY**: Don't Repeat Yourself - reduce repetition by abstracting common functionality

## E
- **Edge Case**: Unusual condition outside normal operating parameters
- **E2E Test**: End-to-end test verifying complete user workflow
- **Entry Criteria**: Conditions that must be met before a phase begins
- **Exit Criteria**: Conditions that must be met before a phase is complete

## F
- **Feasibility Study**: Assessment of project practicality (technical, economic, operational)
- **Functional Requirement**: What a system should do (behaviors, features)

## G
- **Greenfield Project**: New project developed from scratch without legacy constraints

## I
- **Integration Testing**: Verifying interaction between components or systems
- **IaC**: Infrastructure as Code - managing infrastructure through code (Terraform, CloudFormation)

## K
- **KISS**: Keep It Simple, Stupid - advocate for simplicity
- **KPI**: Key Performance Indicator - measurable value demonstrating effectiveness

## M
- **Microservices**: Architectural style with small, independent services communicating over APIs
- **Migration**: Moving from one technology, platform, or architecture to another
- **Modernization**: Upgrading, migrating, or refactoring existing systems
- **MoSCoW**: Prioritization: Must, Should, Could, Won't have

## N
- **Non-Functional Requirement**: How a system should behave (performance, security, reliability)

## P
- **Phase**: Distinct stage in SDLC with specific objectives, steps, outputs
- **PoC**: Proof of Concept - small implementation to demonstrate feasibility

## Q
- **Quality Gate**: Checkpoint that must be passed before proceeding to next phase

## R
- **Refactoring**: Restructuring code without changing external behavior
- **Regression Testing**: Verifying existing functionality still works after changes
- **REST**: Representational State Transfer - architectural style using HTTP methods
- **Risk**: Uncertain event that could affect project objectives
- **Rollback**: Reverting system to previous state, typically after failed deployment
- **Rolling Deployment**: Incrementally updating instances one at a time

## S
- **SDLC**: Software Development Lifecycle - process of planning, creating, testing, deploying
- **Smoke Test**: Basic test verifying most critical functionality
- **SOLID**: Five design principles: Single responsibility, Open-closed, Liskov, Interface segregation, Dependency inversion
- **SWOT**: Strengths, Weaknesses, Opportunities, Threats analysis

## T
- **Technical Debt**: Cost of additional rework from choosing easy solution over better approach
- **TRL**: Technology Readiness Level - measure of technology maturity (1-9)

## U
- **Unit Test**: Test verifying correctness of individual function or method

## V
- **Verbosity**: Level of detail in output (minimal, standard, detailed)

## W
- **WBS**: Work Breakdown Structure - hierarchical decomposition of work into tasks

## Y
- **YAGNI**: You Aren't Gonna Need It - don't add functionality until necessary
